# Data Model: Backend User Registration

**Feature**: `004-backend-user-registration`  
**Date**: 2026-03-31  
**Storage**: DynamoDB

---

## Entities

### User

Represents a registered account stored in DynamoDB.

| Attribute | DynamoDB Type | Required | Notes |
|---|---|---|---|
| `email` | String (PK) | Yes | Normalised (lowercased, trimmed) before storage. Primary key — enforces global uniqueness. |
| `user_id` | String | Yes | Version 4 UUID generated by `crypto.randomUUID()` at registration time. |
| `hashed_password` | String | Yes | bcrypt hash (cost factor 10). Never returned in any response. Never logged. |
| `full_name` | String | No | Optional. Stored as empty string `""` if not provided or only whitespace. Never exposed in registration response. |
| `created_at` | String | Yes | ISO 8601 UTC timestamp set by the system at write time (e.g., `2026-03-31T12:00:00.000Z`). Never returned in registration response (stored only). |

**Table name**: `Users` (injected via `USERS_TABLE_NAME` environment variable)

---

### RegistrationRequest

Represents the inbound JSON body of a `POST /register` request.

| Field | Type | Required | Validation |
|---|---|---|---|
| `email` | string | Yes | Must conform to email format after trimming and lowercasing. Rejected if absent. |
| `password` | string | Yes | Minimum 8 characters. Rejected if absent or too short. |
| `full_name` | string | No | No format constraint. Whitespace-only treated as absent. |

---

### RegistrationResponse

Represents the outbound JSON body on successful registration (HTTP 200).

| Field | Type | Notes |
|---|---|---|
| `id` | string | The `user_id` UUID of the created user. |
| `email` | string | The normalised email address that was registered. |

---

### ErrorResponse

Represents the outbound JSON body on any rejected request (HTTP 400).

| Field | Type | Notes |
|---|---|---|
| `error_type` | string (enum) | One of: `validation_error`, `duplicate_email`, `missing_field`, `malformed_request`, `internal_error` |
| `message` | string | Human-readable description of the problem. Safe to surface to API consumers. |

---

## DynamoDB Table Definition

```yaml
Table: Users
BillingMode: PAY_PER_REQUEST
KeySchema:
  - AttributeName: email
    KeyType: HASH
AttributeDefinitions:
  - AttributeName: email
    AttributeType: S
```

No Global Secondary Indexes are required for this feature. `user_id` is not a key; it is a plain attribute retrieved only via email lookup.

## Access Patterns

| Operation | DynamoDB Action | Key | Condition |
|---|---|---|---|
| Register new user | `PutItem` | PK: `email` | `attribute_not_exists(email)` — atomic duplicate check + write |
| Look up user by email (US3 verification) | `GetItem` | PK: `email` | None |

## State Transitions

```
[Request received]
        │
        ▼
[Validate input] ──── invalid ────► [Return ErrorResponse: validation_error / missing_field / malformed_request]
        │
        ▼ valid
[Normalise email]
        │
        ▼
[Hash password (bcrypt)]
        │
        ▼
[Conditional PutItem] ──── ConditionalCheckFailed ────► [Return ErrorResponse: duplicate_email]
        │
        ▼ success
[Return RegistrationResponse: {id, email}]
```

## Validation Rules

| Rule | Field | Condition | Error type |
|---|---|---|---|
| Required email | `email` | Absent or null | `missing_field` |
| Required password | `password` | Absent or null | `missing_field` |
| Email format | `email` | Does not match email regex after normalisation | `validation_error` |
| Password length | `password` | Fewer than 8 characters | `validation_error` |
| Malformed body | — | Request body missing or not valid JSON | `malformed_request` |
| Duplicate email | `email` | DynamoDB conditional write fails | `duplicate_email` |
